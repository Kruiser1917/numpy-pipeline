# NumPy-пайплайн подготовки данных

Предобработка числового датасета на чистом NumPy, без pandas и scikit-learn: генерация данных, пропуски, выбросы и дубли, разбиение на train и test, масштабирование, проверка и сохранение. Каждый этап — отдельная функция в `pipeline.py`.

## Запуск

Нужен Python 3.10 или новее (проверено на 3.14).

```bash
git clone https://github.com/Kruiser1917/numpy-pipeline.git
cd numpy-pipeline
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 run.py
```

```
1. generate:        X (1000, 8), y (1000,)
2. add_dirt:        строк 1015, NaN 151
3. drop_duplicates: удалено 15 → строк 1000
4. split:           train 800, test 200
5. fit/transform:   standard, NaN осталось 0
6. check:           train mean ≈ 0, std ≈ 1 → OK
7. save:            data/dataset.npz (73.1 КБ)
```

| Параметр | По умолчанию | Что задаёт |
|---|---|---|
| `--rows` | 1000 | сколько строк сгенерировать |
| `--method` | `standard` | масштабирование: `standard` (mean 0, std 1) или `minmax` (от 0 до 1) |
| `--seed` | 42 | seed для воспроизводимости |
| `--out` | `data/dataset.npz` | куда сохранить результат |

Если проверка не прошла, `run.py` завершается с кодом 1, поэтому его можно ставить в CI.

## Этапы

| # | Функция | Что делает |
|---|---|---|
| 1 | `generate_data` | X 1000 × 8 с признаками в разных масштабах и целевой y; признак 1 специально связан с признаком 0 |
| 2 | `add_dirt` | ≈2% пропусков NaN, 20 выбросов на 8–12 std, 15 дублей строк; исходные массивы не меняет |
| 3 | `drop_duplicates` | удаляет одинаковые строки с учётом того, что NaN ≠ NaN |
| 4 | `train_test_split` | перемешивает и делит 80 / 20 |
| 5 | `fit_preprocessor` | **только по train** считает медианы, границы выбросов `Q1 − 3·IQR … Q3 + 3·IQR`, центр и разброс |
| 6 | `transform` | `fill_missing` → `clip_outliers` → `scale` для train, test и любых новых данных |
| 7 | `check_train` | train: mean ≈ 0 и std ≈ 1 (для MinMax: min ≈ 0 и max ≈ 1) |
| 8 | `save_dataset`, `load_dataset` | один `.npz`: выборки и параметры чистки, чтобы так же обработать новые данные |

### Почему порядок отличается от текста задания

В задании стандартизация стоит до разбиения на train и test. Тогда среднее и std считаются по всем данным, и в train «просачивается» информация из test (data leakage), а оценка модели получается завышенной. Здесь сначала разбиение, потом все статистики только по train и применение их к test — как `fit` / `transform` в scikit-learn. Требование «train: mean ≈ 0, std ≈ 1» при этом выполняется точно, а у test среднее близко к 0, но не ровно 0 — так и должно быть.

## Результаты

- **Корреляции.** Самая связанная пара — признаки 0 и 1, r = 0.868; остальные пары около 0. На чистых данных было 0.934: заливка пропусков медианами и обрезка выбросов ослабляют связь, потому что медиана «не знает», что признаки ходят вместе.
- **Время и память** (`python3 benchmark.py`, MacBook Pro):

| Строк | Время, с | Пик памяти, МБ | Сам X, МБ |
|---:|---:|---:|---:|
| 1 000 | 0.039 | 2.1 | 0.1 |
| 10 000 | 0.010 | 4.0 | 0.6 |
| 100 000 | 0.114 | 39.8 | 6.1 |
| 1 000 000 | 1.584 | 397.7 | 61.0 |

Время растёт примерно пропорционально числу строк; первый прогон медленнее из-за прогрева. Пик памяти примерно в 6.5 раз больше самого X: каждый этап создаёт новый массив. Для больших данных помогут `float32` (вдвое меньше памяти) и обработка батчами (`iter_batches`).
